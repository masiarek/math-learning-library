# Sets in Python

**Level:** 101 · for anyone who has written `set(...)` and been surprised by it

**One line:** Python's `set` is the mathematical set plus one rule, that members must be hashable, and almost every set gotcha follows from one of the two: from "a set is only its members", or from "membership is decided by `hash` and `==`", with a third, smaller rule on top: operators insist on sets, methods accept any iterable.

## The two rules

[What is a set?](../what_is_a_set/README.md) ends with the rule mathematics settled on: a set is its members and nothing else, so two sets with the same members are equal. Python's `set` obeys that rule to the letter, and most of what books list as its "characteristics" are consequences of it:

- **No order.** Order is not membership, so `{2, 5} == {5, 2}`. A set can be iterated, but the order it comes out in is an accident of storage, and there is no `s[0]`.
- **No duplicates.** Being a member twice is the same as being a member once, so `{1, 1, 2} == {1, 2}`.
- **One empty set.** `set()`, however it was reached. It is written `set()` because `{}` was already taken by the empty dict.

The second rule is Python's own. A set is a hash table: to decide whether x is a member, Python computes `hash(x)`, looks in that slot, and confirms with `==`. So:

- **Members must be hashable.** A list, a dict or a set can change after it is stored, its hash would change with it, and the set would look in the wrong slot. So `{[1, 2]}` and `s.add(other_set)` raise `TypeError: unhashable type`. A tuple of hashables and a `frozenset` are fine. It is not the same as "immutable": `(1, [2])` is a tuple and still unhashable, because it holds a list.
- **Equal means the same member.** `True == 1 == 1.0` and their hashes agree, so `{True, 1, 1.0, '1', (1,)}` has three members, not five.
- **Membership is fast.** `x in s` is one hash lookup, whatever the size of `s`; `x in some_list` scans the list.

The third rule is about manners, not meaning: `a | b` needs two sets, and `a.union(b)` accepts any iterable, converts it, and takes several at once. The notes this page is merged from say "methods are more forgiving", and section 3 shows exactly how.

## Creating a set (section 1)

There are four ways, and they differ in one respect: what counts as one member.

| Code | Result | Why |
|---|---|---|
| `{'a', 'b', 'c'}` | `{'a', 'b', 'c'}` | braces: each thing written is one member |
| `set(['a', 'b', 'c'])` | `{'a', 'b', 'c'}` | `set()` takes one iterable and adds each item it yields |
| `set('abc')` | `{'a', 'b', 'c'}` | a string is an iterable of characters |
| `set('a', 'b', 'c')` | `TypeError` | `set()` takes at most one argument |
| `{('a', 'b', 'c')}` | `{('a', 'b', 'c')}` | one member, a tuple |
| `{'foo'}` vs `set('foo')` | `{'foo'}` vs `{'f', 'o'}` | whole string vs its characters, deduplicated |
| `{2*x for x in [1, 2, 3]}` | `{2, 4, 6}` | a comprehension: the rule and the source together |
| `s = set(); s.add(...)` | grows one member at a time | `add` takes exactly one member |

The quiz from the notes, "which of these define `{'a', 'b', 'c'}`?", has three right answers: `set('abc')`, `set(['a', 'b', 'c'])` and `{'a', 'b', 'c'}`. The two traps are `set('a', 'b', 'c')`, which passes three arguments where one iterable is wanted, and `{('a', 'b', 'c')}`, which is a set with one member.

A comprehension is also where [Russell](../what_is_a_set/README.md#the-repair-and-the-paradox-as-a-theorem) meets Python. `{x for x in source if rule(x)}` always draws from an existing `source`, which is exactly Zermelo's axiom of separation; Python has no syntax for "every x such that…" with no source, so it cannot state the paradox.

## Adding: one member or many (section 2)

`s1.add(s2)` does not merge two sets. It tries to put `s2` in as a single member and fails, because a set is unhashable. The fixes depend on what was meant:

- merge the members: `s1.update(s2)`, `s1 |= s2`, or a new set `s1 | s2`;
- store the set as one member: `s1.add(frozenset(s2))`.

The same error with a list, `s.add([1, 2, 1])`, has the same cure: freeze it first, `s.add(tuple([1, 2, 1]))`, which gives `{(1, 2, 1)}`. A `frozenset` has the opposite problem: it has no `add` at all (`AttributeError`), so "adding" to one means building a new one, `fs.union([3, 4])` or `fs | {3, 4}`. Wrapping the original in another `frozenset(...)` first, as one of the notes does, is harmless and unnecessary.

There is no `+` for sets. `[2, 3] + [3, 4]` concatenates lists and keeps both 3s; for sets the operation is `|`, and it keeps one.

## Operators and methods (section 3)

| Operation | Operator | In place | Method | Maths |
|---|---|---|---|---|
| union | `a \| b` | `a \|= b` | `a.union(b, ...)` / `a.update(b, ...)` | A ∪ B |
| intersection | `a & b` | `a &= b` | `a.intersection(b, ...)` | A ∩ B |
| difference | `a - b` | `a -= b` | `a.difference(b, ...)` | A ∖ B |
| symmetric difference | `a ^ b` | `a ^= b` | `a.symmetric_difference(b)`, one argument only | A △ B |
| subset | `a <= b` | | `a.issubset(b)` | A ⊆ B |
| proper subset | `a < b` | | none | A ⊂ B |
| superset | `a >= b` | | `a.issuperset(b)` | A ⊇ B |
| proper superset | `a > b` | | none | A ⊃ B |
| disjoint | none | | `a.isdisjoint(b)` | A ∩ B = ∅ |
| membership | `x in a` | | `a.__contains__(x)` | x ∈ A |
| equality | `a == b` | | none | A = B |

`B >= A` reads "B is a superset of A", *B jest nadzbiorem A*. For two sets, every row with both forms returns the same answer; the program asserts it. Where they differ is the right-hand side. `a | (3, 4, 5)` raises `TypeError: unsupported operand type(s) for |: 'set' and 'tuple'`, and `a.union((3, 4, 5))` converts the tuple and works. `X = {1, 3, 5}; X & [1, 5, 9]` fails, and `X.intersection([1, 5, 9])` returns `{1, 5}`. The methods also take several iterables at once, `a.union([9], 'x', range(2))`, except `symmetric_difference`, which takes exactly one.

Why the difference? An operator is a symbol between two values, written infix like `a + b`, and Python makes it strict so that `set | list` does not quietly decide what type the answer should be. A method is a named call on one set, and its name already says the answer is a set, so it can afford to accept any iterable. (Infix, prefix and postfix are the three places an operator can stand: `a | b`, `| a b`, `a b |`. A method call, `union(a, b)`, is the prefix form with brackets.)

The engineers-and-managers example from the notes turns each operator into a question in plain words, and ends with an identity worth remembering: *either, minus exactly one, is both*, (E ∪ M) ∖ (E △ M) = E ∩ M.

## Chaining: what `^` of three sets means (section 5)

The symmetric difference of two sets is "in exactly one of them". Chained over three, `s1 ^ s2 ^ s3` is evaluated left to right as `(s1 ^ s2) ^ s3`, and it is **not** "in exactly one of the three". It is "in an odd number of them". With s1 = {0, 1, 2, 3, 4}, s2 = {2, 3, 4} and s3 = {2, 5}, the element 2 is in all three sets and survives, while 3 and 4 are in two and vanish. The trainer's explanation in the notes, (s1 ^ s2) ^ s3 = {0, 1} ^ {2, 5}, is correct; the counting rule says why it has to come out that way. `{1} ^ {1} ^ {1}` is `{1}`.

Union, intersection and symmetric difference are associative, so the brackets never matter for them. Difference is not: `s1 - s2 - s3` means `(s1 - s2) - s3`, and `s1 - (s2 - s3)` is a different set. That is the "left to right" in the notes' summary, and it only matters for `-`.

## Equality and frozenset (sections 6 and 7)

`a == b` is extensionality run as code: same members, equal, whatever order they were added in. The alternatives in the notes each test something else. `list(a) == list(b)` compares iteration orders, and the program shows two equal sets, `{1, 9}` and `{9, 1}`, whose lists differ. `a.difference(b) == set()` checks only that a ⊆ b, so it says `{1}` "equals" `{1, 2}`. `not (a ^ b)` is correct, and `==` is simpler.

A `frozenset` is a set that cannot change after it is made, so it is hashable and can be a member of a set or a key of a dict. It has no `add`; "adding" builds a new one, `fs.union([3, 4])`. When a set and a frozenset are combined, the left operand decides the type of the result, and `frozenset({1, 2}) == {1, 2}` is True, because equality still looks only at members.

## Subsets, removal, order (sections 8 to 10)

Every set is a subset of itself but not a *proper* subset; that is the whole difference between `<=` (⊆) and `<` (⊂). The empty set is a subset of every set and disjoint from every set, itself included. One mistake from the notes is worth its own line: `if (s1 <= s2, s3):` builds a tuple, and a non-empty tuple is always true, so the test always passes. Write `s1 <= s2 and s1 <= s3`. For the notes' sets, s1 = {0, 1, 2, 3, 4}, s2 = {0, 2, 3, 4} and s3 = {0, 2, 5}, the corrected test is False: 1 is in s1 and in neither of the others. The operator is written `<=` with no space; `< =` is a syntax error.

`remove(x)` raises `KeyError` when x is absent and `discard(x)` does not; `pop()` removes an arbitrary member and raises on an empty set; `clear()` empties it.

`list(set(L))` removes duplicates and may reorder. With small integers the result often *looks* sorted, `[1, 2, 3, 4, 5]`, only because an integer's hash is itself, so it lands in slot n modulo the table size; `list(set([10, 3, 8]))` is `[8, 10, 3]`. With strings the order changes from one run of Python to the next. To remove duplicates and keep the first-seen order, use `list(dict.fromkeys(L))`. A set cannot be sorted, but `sorted(s)` returns a sorted list, and a set of mixed ints and strings needs a key such as `(isinstance(x, str), x)`, because Python 3 will not compare an int with a str.

## What sets are for (section 11)

Three uses cover most real code:

- **Membership tests.** Is this word a stop word, has this ID been seen: one hash lookup each.
- **Removing duplicates**, with the ordering caveat above.
- **Remembering where you have been.** A walk through a graph with cycles keeps a `visited` set and never steps into a node twice. Without it the walk loops forever; with a list instead of a set it works, but each check scans the list.

And the set algebra itself on real data. The keys a database join keeps are a set operation on the two key columns: an inner join keeps customers & invoiced, an outer join customers | invoiced, a left anti-join customers - invoiced, the customers never invoiced. Pandas' `merge(how='inner' | 'outer' | 'left')` is the same algebra with the rows attached.

## Po polsku, w skrócie

`set` w Pythonie to zbiór w sensie matematycznym z jedną dodatkową zasadą: elementy muszą być haszowalne. Prawie każda pułapka wynika z jednej z tych dwóch zasad. Zbiór to wyłącznie jego elementy, więc nie ma kolejności ani powtórzeń, a `{}` to pusty słownik, nie pusty zbiór; pusty zbiór to `set()`. Przynależność sprawdza się przez `hash` i `==`, więc lista czy inny `set` nie może być elementem (`TypeError: unhashable type`), a `True`, `1` i `1.0` to jeden i ten sam element.

Operatory (`|`, `&`, `-`, `^`, `<=`, `>=`) i metody (`union`, `intersection`, `difference`, `symmetric_difference`, `issubset`, `issuperset`) dają dla dwóch zbiorów ten sam wynik, ale operator wymaga zbioru po obu stronach, a metoda przyjmie dowolny obiekt iterowalny. `B >= A` czytamy „B jest nadzbiorem A”. Tylko `isdisjoint` nie ma operatora. Kilka twierdzeń z notatek jest błędnych: `__contains__` działa (to właśnie jego wywołuje `in`), `-` ma metodę `difference`, a `issubset` ma operator `<=`.

Warto zapamiętać, że `a ^ b ^ c` to elementy należące do nieparzystej liczby zbiorów, a nie do dokładnie jednego. Dwa zbiory porównuje się przez `==`. Porównywanie list z nich utworzonych jest błędem, bo ta sama zawartość może mieć inną kolejność.
