# A definition is a test

**Level:** 201 · for anyone who has met a definition made of axioms, such as a vector space

**One line:** In a school book a + b = b + a is a fact about the integers; in Axler's definition of a vector space u + v = v + u is a condition any set can be tested against, and once a set passes, every theorem proved from the conditions is true there without being proved again.

## The same sentence, a different job

[The laws of an operation](../laws_of_an_operation/README.md) showed that the school book's rules for the integers and the linear-algebra book's rules for vectors are the same four laws. They are, but the two books use them for different things.

Serge Lang's *Basic Mathematics* says the integers **have** these properties. The sentence is about one set, and it is true or false of that set.

Sheldon Axler's *Linear Algebra Done Right*, definition 1.20, says something else:

> A *vector space* is a set V along with an addition on V and a scalar multiplication on V such that the following properties hold.

Then comes the list. This is not a fact about any particular set. It is an entry test, and any set that meets every condition gets the name *vector space*. The pay-off comes later: every theorem in the book is proved from the conditions alone, so it is true in every set that passes, including sets nobody had in mind when the theorem was proved.

A programmer knows this move. The definition is an interface: a trait in Rust, an interface in Java, a protocol in Python. Each set that passes is an implementation, and each theorem is a generic function written once against the interface. There is one difference. A compiler checks that the methods exist, but nothing checks that they obey the laws. That is why the program below has to test them.

## Five candidates

Section 2 runs Axler's conditions against five sets. Three pass, and two of those look nothing like arrows.

**ℝ²** is the one everybody expects.

**Functions from {a, b, c} to ℚ** pass too, with functions added and scaled point by point: (f + g)(x) = f(x) + g(x). A vector does not have to be a list of numbers. It can be anything that adds and scales by these rules. Axler makes the same move in the same section: ℝⁿ is the functions from {1, …, n} to ℝ, and a sequence is a function from {1, 2, 3, …}. So one proof, that the functions from *any* set S form a vector space, covers ℝⁿ, the sequences and much else at once.

**The positive numbers** pass with a strange addition: "u + v" means u·v, and "a times v" means vᵃ. The zero vector is 1. Every axiom turns out to be an exponent law in disguise:

| Axiom | What it says here | The school law |
|---|---|---|
| commutativity | u·v = v·u | multiplication commutes |
| associativity | (u·v)·w = u·(v·w), and v^(ab) = (vᵇ)ᵃ | power of a power |
| additive identity | v·1 = v | 1 is the multiplicative identity |
| additive inverse | v·(1/v) = 1 | reciprocals |
| multiplicative identity | v¹ = v | first power |
| distributive | (u·v)ᵃ = uᵃ·vᵃ, and v^(a+b) = vᵃ·vᵇ | power of a product, product of powers |

The program tries only whole-number scalars, because 2^(1/2) is not a fraction and the program computes exactly. The space itself is the positive real numbers with any real scalar, and the exponent laws hold there too.

**ℝ² in floats** fails associativity and distributivity, with the witnesses printed. These are the laws [machine numbers](../../01_Precision/machine_numbers/README.md) found floats lose, for the same reason: each grouping rounds at a different step.

**ℝ² with a(x, y) = (ax, 0)** fails exactly one axiom, 1v = v. Every other condition holds, which you can check by hand in a line each. That makes this candidate the reason the axiom is on the list: without it, a scalar multiplication could throw the second coordinate away and still count.

## Proved once: 0v = 0

Section 3 uses a theorem that Axler proves from the axioms alone, a few pages after the definition:

> 0v = (0 + 0)v = 0v + 0v.

Add the additive inverse of 0v to both sides, and what is left is 0 = 0v. Each step uses one axiom: the distributive property, then the additive inverse, associativity and the additive identity. None of it mentions pairs or functions or numbers.

So the theorem holds in every space that passed, and section 3 shows what it says in each. In ℝ² and in the functions it says what you would expect. In the positive numbers the zero vector is 1, and the theorem says **2⁰ = 1**. A school book usually presents x⁰ = 1 as a convention, chosen so that the exponent laws keep working. Here it is a consequence: once the exponent laws hold, the proof of 0v = 0 forces it.

## Proved once: (−1)v = −v

Section 4 is the next theorem:

> v + (−1)v = 1v + (−1)v = (1 + (−1))v = 0v = 0.

So (−1)v is an additive inverse of v, and additive inverses are unique, so it is *the* additive inverse, −v. In the positive numbers the additive inverse of 2 is 1/2, because 2 "plus" 1/2 is 2 · 1/2 = 1, the zero. So the theorem says **2⁻¹ = 1/2**. Negative exponents are reciprocals for the same reason x⁰ = 1: the laws force it.

## Fail one axiom, lose the theorems that used it

Section 5 goes back to the two candidates that failed.

In ℝ² with a(x, y) = (ax, 0), the theorem of section 4 is false: (−1)(1, 2) = (−1, 0), and (1, 2) + (−1, 0) = (0, 2), which is not zero. Look at the proof. Its first step replaced v by 1v, and 1v = v is the axiom this candidate fails. The theorem breaks exactly where the proof used the missing axiom.

In floats, the cancellation law (u + v) − v = u is proved from associativity, and it fails: (0.1 + 0.2) − 0.2 comes out as 0.10000000000000003. But 0v = 0 and (−1)v = −v both still hold, because multiplying a float by 0 or by −1 happens to be exact. So a failed axiom does not make every theorem false. It makes every theorem that used it **unproved**. Some survive by luck, and there is no way to tell which without checking each one. That is why computing with floats is a subject of its own, and not a chapter of linear algebra.

## The same move, everywhere

Vector spaces are one example. Every name in [the laws of an operation](../laws_of_an_operation/README.md) is a definition of this kind, and every theorem proved from one is proved once:

- **An identity is unique**, in any set with an operation. If e and e′ are both identities, then e = e · e′ = e′. That one line covers 0 for the integers under +, 1 for the integers under ×, the empty string, and the identity matrix.
- **A polynomial of degree n has at most n roots** in any field. [Roots of unity](../../03_Complex_Numbers/roots_of_unity/README.md) uses this to know it has found every solution of zⁿ = 1. It never proves the theorem for the complex numbers. It only needed [multiplication as pairs](../../03_Complex_Numbers/multiplication_as_pairs/README.md) to show that the pairs are a field.

This is the honest answer to "every book repeats itself". A book that states the laws as a *definition* is doing the opposite of repeating: it is setting up a test, so that each proof after it has to be written only once.
