# Lessons learned

Pitfalls met in earlier sessions. Check here before repeating an approach.

- **Wikipedia, Math is Fun, ChiliMath and the Stanford Encyclopedia are blocked** by the network policy too, like YouTube. Describe such a page from memory, say so on the page, and add a "how sure" column where the claims matter.
- **YouTube is blocked** in cloud sessions by the network policy. Find the title with a web search on the video ID, then ask the owner for the transcript or description.
- **The owner's external drive and Downloads folder are unreachable** from cloud sessions. Search Google Drive first; otherwise ask the owner to upload the file or run a local session (`claude remote-control` in the repo folder). A manual that ships with open-source software usually has its source on GitHub: read that instead.
- **Chapter `README.md` files have paragraphs of many kilobytes on one line.** Do not pipe them through `rev`, `cut` and friends in long chains (one such command hung until killed); slice them with a short Python script.
- **A new example has no answer key**: run `python3 tools/run_examples.py --only <stem> --update` once, then the plain check.
- **After a pull request is merged**, restart the working branch from `origin/master` before new work. The push is then a fast-forward; force pushes are denied in `.claude/settings.json` and must not be worked around.
- **Studies cited from memory** (author, year, journal) should be said to be from memory in the reply, so the owner knows they were not looked up.
- **The Polish summaries use „ and a plain " as closing quote.** When editing one with a Python script, wrap the match strings in triple quotes; a double-quoted string ends at the first ".
- **The container's Python rejects an f-string whose expression reuses the outer quote** (`f"{"#"}"` is a SyntaxError). Use the other quote type inside.
- **Write edit scripts to a file in the scratchpad and run them**, rather than inline heredocs: a Python syntax error inside a 100-line heredoc costs the whole batch, and `\"` inside a quoted heredoc ends the Python string. Avoid double quotes inside f-strings; use typographic “ ” in prose.
- **Glossary entries have `{ #slug }` anchors on their own line after the entry** (attr_list). At the end of the entry's line the marker is rendered as literal text and makes no id; 216 entries were wrong that way for one session, and `mkdocs build --strict` only reports it at INFO level, so grep the built `site/GLOSSARY.html` for `<p id="` after changing them. link a term as `GLOSSARY.md#<term-slugged>`; a link to the bare glossary lands at the top, which the owner noticed. New entries need the anchor too; a script that slugs the bold term adds it.
- **A universe for the model checker must contain the witness set.** The two-cycle a = {b}, b = {a} satisfies foundation on its own; it fails only once the pair {a, b} is a point. Build the set the exercise names into the universe before claiming an axiom fails.
- **Never `git checkout -- <file>` to undo a failed edit script on a dirty tree.** A script that asserts before `write_text` leaves the file untouched when it fails; the checkout instead discarded the earlier uncommitted edits to `GLOSSARY.md`, which had to be recovered by re-running the glossary parts of two older scripts. Look at `git diff <file>` first, or write scripts so each one can be re-run.
- **A grid check must not be padded with `or True`.** The first draft of the circle section printed a True that tested nothing; `is_function`-style checks have to compute the claim, and the output is only worth recording once they do.
- **A convention stated on a page needs its owner named.** The precedence page gave Python's place for set difference as "the textbook order", and an answer from another AI tool caught it. When a page states an order, a notation or a rule, say whose it is (which book, which language), and check that a claim that it "follows from logic" holds for every operator in it: ∖ is two connectives, so logic places it nowhere.
- **raw.githubusercontent.com is reachable**, while github.com pages, docs.python.org, postgresql.org and most documentation sites are not. Read a system's own files there (Lean's `Init/Core.lean`, Isabelle's `.thy` files and the LaTeX of its manuals) instead of citing them from memory.
- **A pasted precedence exercise can pass under the readings it claims to rule out.** Asserting the final set is not a test: evaluate the expression under every full bracketing (Catalan many) and count how many give the expected set, as `set_katas` section 9 does; an operand reused on both sides of `-` can make two readings agree for every choice of sets.
- **A book verdict from memory can be wrong on the page sent next.** Larson was reviewed from memory as the plainest of the classroom books; its distance-formula pages, sent minutes later, derive with a reason beside every line. Mark a from-memory verdict as such and expect to correct it when pages arrive.
- **podstawaprogramowa.pl and kmk.org are blocked** too, so school curricula are written from memory with a how-sure table; the owner can confirm the Polish side.
